# Release review checklist

- [ ] Confirm responsibility, proposed repository name and publication state.
- [ ] Complete licensing/security findings and preserve provenance.
- [ ] Record exact target, toolchain, SDK, build configuration, command and warnings.
- [ ] Record host tests and actual hardware acceptance separately.
- [ ] Verify update regions, configuration retention and recovery claims.
- [ ] Identify unsupported targets; keep WBA6 Pending without evidence.
- [ ] Check internal links, status labels, authorship and commercial contact.
- [ ] Check approved documentation attribution and explicit firmware/tooling/branding boundaries.
- [ ] Review logo/avatar provenance and separately staged organization profile.
- [ ] Reconcile reported Probe recovery and no-extra-recording-gate claims with the exact recovered build/logs; do not repeat obsolete detached status.
- [ ] Remove unverified performance, certification or product-availability claims.
- [ ] Record hashes and the exact reviewed commit.
- [ ] Obtain founder approval; record publication only after it occurs.

For the central documentation repository, firmware build/hardware checks are not applicable; evidence concerns documentation and the bounded claims it makes. See [release evidence fields](../provenance/release-evidence.md).

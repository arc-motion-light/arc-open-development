# Publication and release preparation

Each ARC repository has its own publication review. Start with [repository preparation](repository-preparation.md), then complete [licensing](licensing-checklist.md), [security](security-checklist.md) and [release review](release-checklist.md). The [founder-approval policy](founder-approval.md) defines the authorization needed before release.

For engineering capabilities and evidence limits, see [current development status](../docs/development-status.md). Internal Phase 1/1B review reports, audit captures and exact approval records are maintained privately outside the public Git tree. Public documentation should describe capabilities and applicable policies rather than expose internal review records.

Update the [repository registry](../repositories/repository-registry.md) only after an approved publication actually occurs. Publication approval and organization-avatar changes are separate decisions. Checklists and documentation preparation are not approval themselves.

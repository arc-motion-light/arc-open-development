# Open development principles

ARC uses “open development” to describe transparent engineering practices, not to claim that every work carries an open-source license.

1. State what runs today, what is being tested and what is planned.
2. Preserve source histories and authorship evidence; never reconstruct dates to create a stronger narrative.
3. Explain boundaries between control, connectivity, configuration and telemetry.
4. Keep public engineering discussion separate from operational secrets and personal data.
5. Apply licenses only to material the rights holder can license.
6. Obtain explicit hardware evidence before claiming deployment reliability or power-loss recovery.
7. Maintain an honest commercial contact and decide commercial terms in separate agreements.

The current platform illustrates these principles: WBA records history while G4 retains safety authority, but secure Probe assignment and cold-power network recovery remain unfinished. Publication is a reviewed engineering and rights decision, not an automatic consequence of a successful build.

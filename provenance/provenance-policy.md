# ARC Development Provenance Policy

Preserve original Git repositories and full histories, including authors/contributors, commits, tags and relevant development context. Keep authentic build/test records, hardware revisions, design decisions and demonstration evidence. Do not rewrite authorship, backdate commits or fabricate release dates.

Git records are evidence of development activity, not conclusive proof of legal ownership. Maintain rights documentation, contribution agreements, vendor provenance and employment/contract context where relevant. Distinguish authored work, generated code, third-party content and AI-assisted material.

For every future public distribution, retain the original private source and record the exact public candidate. If sanitization requires a separate history or export, document removed categories without revealing secrets and keep a private mapping from original commits to published content. Never silently describe a clean export as the complete original history.

Each milestone must identify source, date type, verification status and limits. Separate test execution from proposed acceptance criteria and link claims to evidence that actually supports them. Release evidence records exact toolchain, SDK, hardware/build target, artifact hashes and results.

This repository's first commit records documentation preparation; it does not transfer, import or replace the firmware histories. See [release evidence](release-evidence.md) and [history template](../templates/development-history.md).
